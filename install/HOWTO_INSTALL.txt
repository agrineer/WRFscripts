Current versions are WRFV4.8.0 and WPSv4.7.0

# Decide where to put WRFscripts and untar WRFscripts.tar.gz
# eg. /home/user

$ cd ~
$ tar xvfz WRFscripts.tar.gz

or git clone:

$ git clone https://github.com/agrineer/WRFscripts

# TO INSTALL:

# change directory to WRFscripts install directory:
eg.
$ cd ~/WRFscripts/install

# Edit the file "install_wrf_variables.bash" to suit your type of WRF implementation.
Currently, the serial implementation is stable, so use SERIAL_IO.

# This bash shell file sets the environment variables that specify how to compile the libraries and WPS/WRF.
# Below are the variable descriptions and default values:

	  WRF_SCRIPTS=/home/user/WRFscripts
	  Sets the location of where WRFscripts.tar was extracted to or
	  cloned to.  Change "/home/user/" to your choice of location.

	  INSTALL_WRF_NUM_CORES=4
	  Sets the number of cores to use for compilation.
	  A higher number has, on occasion, confused the compiler.
	  
          INSTALL_WRF_IO_TYPE=SERIAL_IO
	  Options are: SERIAL_IO, PNETCDF_IO, NETCDFPAR_IO, ADIOS2_IO
	  Stable option is SERIAL_IO and the other options are under
	  construction.

          INSTALL_WRF_OUTPUT_DIR=DEFAULT
          Determines if to create the output directory, or to set the 
	  link path or to take no action.

	  Options are:
	    - DEFAULT
	      Creates the output directory, ${WRF_SCRIPTS}/wrf/output.
	      In case of a rebuild (not a cloned install), and if the output
	      directory or link already exists it will be skipped (no action).
	      	      
	    - Path to existing output directory which gets linked
	      in ${WRF_SCRIPTS}/wrf. If the output directory or link already exists
	      it will be skipped (no action).

            - NONE
	      This option ignores making or linking the output directory and
	      takes no action. The user will manually fix.

          INSTALL_WRF_GFS_DIR=DEFAULT
	  Determines if to create the input ${WRF_SCRIPTS}/wrf/gfs_0.25
	  directory, or to set the link path, or to take no action.
	  Options are:
	     - DEFAULT
               Creates the input ${WRF_SCRIPTS}/wrf/gfs_0.25 directory,
               ${WRF_SCRIPTS}/wrf/gfs_0.25. In case of a rebuild
               (not a cloned install), and if the gfs_0.25 directory
               or link already exists it will be skipped (no action).

             - Path to an existing GFS directory and gets linked to
               in $WRF_SCRIPTS/wrf. If the directory
	       ${WRF_SCRIPTS}/wrf/gfs_0.25 or link already exists it
	       will be skipped (no action).

             - NONE
               Ignores making or linking the gfs_0.25 directory and
               takes no action. The user will manually fix.


          INSTALL_WRF_WPS_GEOG_DIR=DEFAULT
	  Determines if the large WPS_GEOG data directory gets downloaded
	  from UCAR, or to set the link path or to take no action.

          Determine if to the input ${WRF_SCRIPTS}/wrf/WPS_GEOG
	  directory, or to set the path to linked to or to take no action.
          Options are:
          - DEFAULT
            Downloads from UCAR the WPS static data and creates
            ${WRF_SCRIPTS}/wrf/WPS_GEOG. In case of a rebuild
	    (not a cloned install), and if the WPS_GEOG directory or
	    link already exists it will be skipped (no action).

          - Path to existing WPS_GEOG directory and gets linked in
	    ${WRF_SCRIPTS}/wrf

          - NONE
            Ignores making or linking the WPS_GEOG directory.The user will
	    manually fix.
	    
	  INSTALL_WRF_MPI=MPICH
	  Specifies what type of MPI to use, ie. MPI memory access mode
          Options are:
	   - MPICH (use this option as the others are currently under
	     development)
	     Used for communication between nodes and node cores.
	     
	   - OPENMP
	     Used for comunication between a node's cores.
	     
	   - MPICH+OPENMP
	     Used to specify a hybrid comunication.
	     
	  MPICH+OPENMP and OPENMP implementation is still being developed
	  and should not be used currently.

	  INSTALL_WRF_IO_CHANNEL=ch4:ucx
	  Determines IO channels (communication transport) to use
	  Options are:
	  - ch3:nemesis (legacy)
	  - ch4:ofi (does not work with CUDA)
	  - ch4:ucx (default)

          INSTALL_WRF_CUDA_DIR=NONE
	  Determines if GPU libs are used in the MPICH compile.
          CUDA is not used in WRF, but can be used elsewhere in other projects
          Options are:
	    - NONE
	      Does not use CUDA libraries.

            - Path to CUDA directory, eg. /usr/local/cuda
              NOTE: Does not compile with ch4:ofi.
                    Compiles and runs with ch3:nemesis and ch4:ucx.
	      NOTE: CUDA implementation does not work with MAC OS/X.

# Make these options active by sourcing the edited file
$ source install_wrf_variables.bash". This should be done in a bash shell:

# If you are not using bash, you can
# activate a bash shell in your terminal:
$ exec bash

# and then:
$ source install_wrf_variables.bash 

# run the INSTALL shell program with:
$ ./INSTALL.bash 2>&1 | tee WRFscripts-build.txt

# Use "tee" to keep a copy of the build output. Install time can take
# over an hour, depending on the platform used.

# With a succesfull install, link the $WRF_SCRIPTS/wrf to a convienient locator,
eg.
$ cd ~
$ ln -s $WRF_SCRIPTS/wrf

# This link makes navigation to "wrf" easier without going through "WRFscripts. Indeed, "WRFscripts" top directory will not be needed from this point on.

# If you did not download the "WPS_GEOG" in your install, ie. by setting INSTALL_WRF_WPS_GEOG=NO, link your existing "WPS_GEOG" directory in the "~/wrf" directory.
eg.
$ cd ~/wrf
$ ln -s /data/WPS_GEOG

# If you have a separate "gfs_0.25" directory you should remove the "gfs_0.25" directory in the "wrf" directory and put your "gfs_0.25" link in the  "~/wrf" directory.
eg.
$ rm -r gfs_0.25
$ ln -s /input/gfs_0.25

# Populating sector geo directories. This is now done automatically, but if you need
# to re-populate manually:

$ cd ~/wrf/sectors/ANDES03/wps

eg. geog_data_path = '${WRF_SCRIPTS}/wrf/WPS_GEOG'

# Run geogrid.exe to populate the static geo files for your sector.
$ ./geogrid.exe

# Runtime environment variables (not needed for the installation):


# Fill out these varibles in .bash_profile
# and source it for user configuration. see the install/bash_profile_example.

export WRF_HOME=~/wrf          # here the "wrf" directory is
                               # linked to $WRF_SCRIPTS/wrf
			       
export WRF_MPI=MPICH           # specifies type of MPI. If MPICH then
                               # runtime program will look for the hosts
			       # file, unless a HPC job control (JCL)
			       # is specified.
			       
export WRF_OPENMP_NCORES=NONE  # if using OPENMP specifies number cores
                               # to use (under construction)

export WRF_JCL=NONE            # specifies the JCL to use (SLURM,PBS,NONE) no PBS yet

# The export below is used for non-JCL MPICH, eg. desktop and small networked
# computers.
export WRF_MPICH_HOSTS=~/mpd.hosts

export FI_PROVIDER=tcp # for MAC OS/X

# reset load library path to include ~/wrf/lib, similar to:
export LD_LIBRARY_PATH=~/wrf/lib:/usr/local/lib:/usr/lib:/lib

# reset execution path to include ~/wrf/bin, simlarlar to:
export PATH=~/wrf/bin:/usr/local/bin:/usr/bin:/bin:/sbin
				   				   
# The Format for mpd.hosts is simple:

# host:slices
curiosity:4
opportunity:4

# Where "host" is the name of the computer to use and "slices" are number
# of cores to use in each host.

# Running WRF:
usage: runwrf [-h] -s SECTOR -r RESTART -b BEGIN_HOUR [-d RUNDATE]

-s option specifies sector to use, eg. ANDES03.
   SECTOR refers to a defined regional focus, option is mandatory.
   
-r is a flag for restarting a run. RESTART=true/false. Option is mandatory.
   Setting -r false starts a continuous run.
   Setting -r true continues the run from the day before.

-d RUNDATE. Format is YYYYMMDD. If it is not given then the run will use yesterday's date (useful in a "cron" implementation)

# Example runs:

$ runwrf -b 6 -s ANDES03 -r false &

# & puts the job in background. This is not needed, but allows the user to monitor output files in the same terminal shell.

# Continue a previous run for a specific date
$ runwrf -s ANDES03 -r true -d 20260902 & 

# To monitor pre-processing, WRF run must in background or in another terminal
$ cd ~/wrf/log
$ tail -f SECTOR.log    # eg. ANDES03.log. Use Cntrl-c to stop the "tail".
