How to install WRFscripts and WRF/WPS from scratch.
Current versions are WRFV4.8.0 and WPSv4.7.0

# Decide where to put WRFscripts and untar WRFscripts.tar.gz
# eg. /home/user/WRFscripts

$ cd ~
$ tar xvf WRFscripts.tar.gz

or git clone:

$ git clone https://github.com/agrineer/WRFscripts

# TO INSTALL:
# change directory to WRFscripts
$ cd WRFscripts

Edit the file "install_wrf_variables.bash" to suit your type of WRF implementation, ie. serial or parallel IO. Currently the serial and pnetcdf implementations are stable, However, pnetcdf version doesn't seem to improve execution time. Best practice is to start with the default implementation, SERIAL_IO.

This bash shell file sets the environment variables that specify how to compile the libraries and WRF.

	  WRF_SCRIPTS sets the location of where WRFscripts.tar was extracted or
	  cloned.  Change "/home/user/" to your environment.
	  
	  WRF_SCRIPTS=/home/user/WRFscripts
	  
          INSTALL_WRF_IO_TYPE=SERIAL_IO
	  Options are: SERIAL_IO, PNETCDF_IO, NETCDFPAR_IO, ADIOS2_IO
	  Stable options are SERIAL_IO and PNETCDF_IO,
	  Other options  are under construction.

	  INSTALL_WRF_WPS_GEOG=YES
	  Options are: YES and NO
	  This determines if the large WPS_GEOG data gets downloaded.
	  If you already have WPS_GEOG data use the NO option and after
	  installation link your WPS_GEOG directory in the $WRFscripts/wrf
	  directory

	  INSTALL_WRF_MPI=MPICH
	  Specifies what type of MPI to use.
	  Options are: MPICH, OPENMP, MPICH+OPENMP
	  MPICH is stable. MPICH is used for communication between HPC nodes
	  OPENMP is used for comunication between a node's cores.
	  MPICH+OPENMP is used to specify a hybrid comunication.
	  OPENMP implementation is still being developed.

	  INSTALL_WRF_IO_CHANNEL=ch4:ofi
	  Current options are: ch3:nemesis,ch4:ofi,ch4:ucx
	  These specify what kind of communication transport to use.
	  Note that ch3 is a legacy transport.

          INSTALL_WRF_USE_CUDA=NO
	  Options are NO and YES
	  Specifies if GPU (CUDA) is compiled in the MPICH MPI.
	  This option is not yet implemented.

Make these options active by sourcing the edited file "install_wrf_variables.bash". ie.
$ source install_wrf_variables.bash 

# run the INSTALL shell program with:
$ ./INSTALL.bash 2>&1 | tee WRFscripts-build.txt

# Use "tee" to keep a copy of the build output. Install time can take over an hour, depending on ....

-------------------------------------------------------------------------------
# With a succesfull install, link the $WRF_SCRIPTS/wrf to a convienient locator,
eg.
$ cd ~
$ ln -s $WRF_SCRIPTS/wrf

# This link makes navigation to "wrf" easier without going through "WRFscripts. Indeed, "WRFscripts" will not be needed from this point on.

# The construction of the directory "wrf" is now almost complete but for populating SECTOR/wps and some links, if needed.

# If you did not download the "WPS_GEOG" in your install, ie. by setting INSTALL_WRF_WPS_GEOG=NO, link your existing "WPS_GEOG" directory in the "~/wrf" directory.
eg.
$ cd ~/wrf
$ ln -s /data/WPS_GEOG

# If you have a separate "gfs_0.25" directory you should remove the "gfs_0.25" directory in the "wrf" directory and put your "gfs_0.25" link in the  "~/wrf" directory.
eg.
$ rm -r gfs_0.25
$ ln -s /input/gfs_0.25

# Populate sector geo directories,
eg.
$ cd ~/wrf/sectors/ANDES03/wps

# Edit "namelist.wps" and "namelist.wps.template" files to point to "WPS_GEOG directory
eg. geog_data_path = '/home/user/wrf/WPS_GEOG',

# run geogrid.exe to populate the static geo files
$ ./geogrid.exe

-------------------------------------------------------------------------------
# Adjust the file "SECTOR/wrf/namelist.input", if needed, where SECTOR is a predefined regions, eg.ANDES03.

# If running pnetcdf io:
   go to wrf/sectors/XXXXXXX/wrf
   edit namelist.input.template
   under &time control:
   io_form_history                     = 11
   io_form_restart                     = 11
   io_form_input                       = 2
   io_form_boundary                    = 11    

# If running netcdfpar io:
   go to wrf/sectors/XXXXXXX/wrf
   edit namelist.input.template
   under &time control:
   io_form_history                     = 13
   io_form_restart                     = 13
   io_form_input                       = 2
   io_form_boundary                    = 13

# default in distribution, no need to edit namelist.input if using INSTALL_WRF_IO_TYPE=SERIAL_IO
#If running serial io:
   go to wrf/sectors/XXXXXXX/wrf
   edit namelist.input.template
   set io_form_* to 2

For all cases above leave io_form_geogrid = 2 in the namelist.wps.template

# Runtime environment variables (not needed for the installation):


# Fill out these varibles in .bash_profile
  and source it for user configuration. see bash_profile_example.

eg.
export WRF_HOME=/home/user/wrf     # here the "wrf" directory is
                                   # linked to $WRF_SCRIPTS/wrf
				   				   
export WRF_MPI=MPICH               # specifies type of MPI. If MPICH then
                                   # runtime program will look for the hosts
				   # file, unless a HPC job control (JCL)
				   # is specified

export WRF_JCL=NONE                # specifies the JCL to use (SLURM,PBS,NONE)

export WRF_OPENMP_NCORES=NONE      # if using OPENMP specifies number cores
                                   # to use (under construction)

export WRF_MPICH_HOSTS=/home/user/mpd.hosts # used for non-JCL MPICH, eg.desktop and small networked computers. Format for mpd.hosts is simple:

# host:slices
curiosity:4
opportunity:4

# Where "host" is the name of the computer to use and "slices" are number of cores to use in each host.

# Start processing....

# A convienient place to run WRF is from ~/wrf/log, but it can be run from anywhere.
$ cd ~/wrf/log

# Get yesterday's GFS files
$ getdata_gfs.py

or

# Get specific date Global Forecast System (GFS) files
$ getdata_gfs.py YYYYMMDD

NOTE: getdata.py is UTC based, so your location's yesterday might be different from UTC's yesterday. This will be addressed in the future.

NOTE: that GFS files are only available for 10 days. To go back beyond
      the 10 days you need to go to an archive site. (TODO: where and how to decode name)

NOTE: getdata_gfs.py will report errors for days it does not have, you can ignore those.

# Running WRF:
usage: runwrf [-h] -s SECTOR -r RESTART -b BEGIN_HOUR [-d RUNDATE]

-s option specifies sector to use, eg. ANDES03.
   SECTOR refers to a defined regional focus, option is mandatory.
   
-r is a flag for restarting a run. RESTART=true/false. Option is mandatory.

-d RUNDATE. Format is YYYYMMDD. If it is not given then the run will use yesterday's date (useful in a "cron" implementation)

# Example runs:

$ runwrf -b 6 -s ANDES03 -r false &

# & puts the job in background. This is not needed, but allows the user to monitor output files in the same terminal shell.

# Continue a previous run for a specific date
$ runwrf -s ANDES03 -r true -d 20260902 & 

# To monitor pre-processing, WRF run must in background or in another terminal
$ cd ~/wrf/log
$ tail -f SECTOR.log    # eg. ANDES03.log. Use Cntrl-c to stop the "tail".
